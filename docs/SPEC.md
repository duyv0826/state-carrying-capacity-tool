## 0. 本次 Spec 锁定的六条硬决策（开发前必读）

1. **题单锁 9 题**（A3 + B3 + C3 三因子），`schema_version = 2`。上线后改题必须递增版本，新旧样本不得混跑 EFA。
2. **结果前置**：第 9 题答完立即出「结果预览」，再进 S1–S3 背景题，最后单次提交。**不得把结果锁到最后一步。**
3. **步序由 `flow.steps.ts` 配置驱动**，禁止在组件里写死步数或题号。理由：保留切换到「方案 B（S2/S3 前移回第 0 步）」的能力，切换只改一个数组。
4. **采集与功能解耦**：`collection_enabled = false` 时工具 100% 可用且零采集（应对 IRB 未获批）。
5. **部署目标：中国香港或新加坡轻量**（免备案、国内可达）。有备案域名后可迁回广州，只改 DNS。
6. **图标库唯一来源 `lucide-react ^1.43.0`**（2026-09-10 `npm view` 实测，ISC 许可）。禁止 emoji、禁止第二套图标库。

## 1. 产品定义

- **一句话描述**：让创意从业者用 9 道题评估自己某个常用软件的「状态承载量」，得到它被生成式 AI 替代的风险档位与逐维度解释。
- **目标用户**：内容运营者、游戏/交互设计学生与从业者（即研究者本人所在群体，便于 practice-based research 取样）。
- **核心问题**：现有「AI 替代风险」测评要么测职业（测不到软件差异），要么测软件（测不到使用者差异），且分数不可解释。本工具把分析单位放在**「使用者 × 他自己那个具体软件」**这一层。
- **双重身份**：学位作品形态（practice-based research）＋ 论文数据采集装置（目标 N≥200 入库样本）。

## 3. 明确不做（Out-of-Scope）

| 不做的功能 | 原因 | 何时考虑 |
|------------|------|----------|
| **AI 生成行动建议** | 用黑箱解释一个宣称可解释的量表，自毁方法论立场 | 永不（除非改为可审计的规则引擎） |
| 用户注册 / 登录 / 账号体系 | 匿名采集，隐私最小化；引入账号即违反最小化原则 | 永不 |
| 跨设备查看历史结果（`/result/:id` 可分享链接） | 需引入身份标识，与匿名冲突 | 若 IRB 批准且样本量不足时评估。注：2026-09-26 已以**匿名 `record_id` 令牌**形式落地（见 §13），令牌单向派生、视图不含任何可识别字段，**不构成**此处禁止的"身份标识"方案 |
| 软件库自动补全（接第三方软件数据库） | 依赖外部数据源，MVP ROI 不足 | v2.0 |
| 社交分享 SDK / 一键转发 | 分享走 PNG 卡片，不需要 SDK | v2.0 |
| 多维常模对比（同软件他人得分对比） | 需 N≥150 且分软件分层，MVP 样本不支持 | N≥150 后 |

## 5. API 端点清单（锁定，6 个）

| Method | Path | 功能 | 认证 | 备注 |
|--------|------|------|------|------|
| GET | `/api/v1/config` | 取 `collection_enabled`、`consent_version`、档位基线 | 无 | 前端据此决定是否采集、用哪套知情同意文案 |
| POST | `/api/v1/submissions` | 写入一条自测记录 | 无 | 服务端算反转分/因子分/总分/档位/质量标记；`hp` 蜜罐非空时静默成功但不入库 |
| POST | `/api/v1/abandon` | 记录中途放弃发生在第几题 | 无 | 受 `collection_enabled` 统一管控 |
| POST | `/api/v1/followups` | 后续联系意向（物理分表） | 无 | 联系方式与作答数据分离存储，导出时排除 token 列 |
| GET | `/api/v1/admin/export` | 导出全量数据 CSV/JSON | 环境变量令牌 | 供 SPSS/R/Python 分析 |
| GET | `/api/v1/admin/codebook` | 导出变量字典 | 环境变量令牌 | 保证数据可解释 |

**Strata 取值（已补 enum，2026-09-10）**：
- S1：`A` / `B` / `C`（陈述型，绝不可呈现为 Likert 量表样式）
- S2：`lt6m` / `6m_2y` / `2y_5y` / `gt5y`（半开区间，无重叠无空隙）
- S3：`daily`(≥5天/周) / `weekly_multi`(2-4次/周) / `weekly_once`(约1次/周) / `monthly`(1-3次/月) / `rarer`
- S4：`self` / `mandated`
- 切法随 `schema_version` 锁定，改边界必须升版本，**不得原地改写语义**

## 6. 数据库表清单（锁定）

| 表 | 核心字段 | 约束要点 |
|----|----------|----------|
| `submissions`（主表） | `id`(UUIDv4 PK) / `session_id`(仅关联同人连测多软件，不跨会话追踪) / `created_at` / `schema_version`(**=2**) / `max_score`(45) / `consent_version` / `consent_mode` / A1–C3 原始分 / `total_score`(9–45) / `straightlining_flag` / `band` / `band_basis`(prior\|quantile\|kmeans) / S1–S4 | 字段完整定义见 ARCHITECTURE.md §数据模型；S2/S3/S4 加 CHECK 约束 |
| `followups` | 联系意向 | **物理分表**，与作答数据不共用表；导出时排除 token 列 |

**隐私最小化硬约束**：IP 仅在内存参与限流，**绝不落库**；地区不由 IP 推断，由被试自愿填写。

## 7. 页面清单（锁定）

| 路由 | 内容 | 步序 | 对应 API |
|------|------|------|----------|
| `/` | 第 0 步：选软件 + 知情同意 | 步 1 | GET `/config` |
| `/q/:id`（1..9） | 第 N 题（5 点 Likert，一屏一题） | 步 2–10 | —（本地计分） |
| `/preview` | **结果预览**（第 10 步的产出画面，非独立步） | 步 11 | —（不发请求） |
| `/s/:id`（S1/S2/S3） | 背景信息（S4 与 S3 同屏） | 步 12–14 | — |
| `/result/:sessionId` | 结果页（提交后 / 「到此为止」本地结果两种入口） | 终 | POST `/submissions` |

**步序与进度播报规则**（UIUX §4.1.2b，前端必须实现）：
- 进度轨 **14 段分两组**：核心 11 段 + 背景 3 段，组间 gap 8px
- 背景组未答段用 `--color-border-subtle`（比核心组更淡）——**视觉降级是结果前置生效的必要条件**
- `aria-valuemax = 14`；题号播报「第 3 / 9 题」，步数播报「第 4 步，共 14 步」，两者并存且不得混用
- 第 9 题按钮文案禁止出现「提交」「完成」
- 知情同意明示：「10 步出结果 + 3 步背景信息 + 最后一题可跳过，全程约 3 分钟」

## 9. 验收标准（EARS 格式，QA 唯一依据）

| 编号 | 功能 | EARS 验收标准 | 优先级 |
|------|------|---------------|--------|
| AC-01 | 选软件 | While 用户在第 0 步，系统**必须**同时提供常见软件预置项与自由输入框；If 输入为空，系统**必须**禁用进入第 1 题 | P0 |
| AC-02 | 量表作答 | When 用户选择某一 Likert 选项，系统**必须**自动前进到下一题且允许回退修改 | P0 |
| AC-03 | 结果前置 | When 用户答完第 9 题，系统**必须**在进入背景题之前展示结果预览，且**必须**只显示档位与三因子雏形，不显示逐维度完整解释 | P0 |
| AC-04 | 进度降级 | While 用户处于背景题阶段，系统**必须**将未答的背景段渲染为 `--color-border-subtle`，视觉上弱于核心段 | P0 |
| AC-05 | S1 呈现 | While 展示 S1，系统**必须**以三行陈述 + 序号 A/B/C 呈现，**不得**渲染为 5 格等距量表；S1 **必须**无默认值 | P0 |
| AC-06 | 提交 | When 用户完成 S3（S4 可选），系统**必须**以单次 POST 提交 scores + strata，且 `strata` 非空 | P0 |
| AC-07 | 服务端算分 | If 收到合法提交，系统**必须**计算反转分、三因子分、总分(9–45)、档位与质量标记后落库 | P0 |
| AC-08 | 蜜罐 | If `hp` 字段非空，系统**必须**返回成功状态码但**不得**写入数据库 | P0 |
| AC-09 | 采集开关 | While `collection_enabled = false`，系统**必须**禁用所有采集端点，且工具核心流程**必须**保持 100% 可用 | P0 |
| AC-10 | 隐私 | 系统**必须**确保 IP 不落库；If 地区字段有值，该值**必须**来自被试自愿填写而非 IP 推断 | P0 |
| AC-11 | 步序可配 | 前端步序**必须**由 `flow.steps.ts` 配置驱动；If 修改该数组，步序**必须**随之改变，无需改动组件 | P0 |
| AC-12 | 分享卡片 | When 用户点击导出，系统**必须**生成 1080×1350 PNG，且**必须**固定为浅色主题（不受当前深色模式影响） | P0 |
| AC-13 | 放弃埋点 | When 用户中途关闭，系统**必须**记录 `last_question_index` | P1 |
| AC-14 | 无障碍 | 所有 Likert 选项**必须**可键盘操作；进度元素**必须**带 `aria-valuenow/valuemax/valuetext` | P0 |
| AC-15 | emoji | 全代码库**必须**通过 emoji 正则扫描，命中数为 0 | P0 |

## 10. 边界与约束

- 不支持 IE；响应式断点 xs <640 / sm ≥640 / md ≥768 / lg ≥1024
- 移动端 xs：Likert 纵向堆叠（行高 48px），底部操作行全宽纵向
- 性能目标：首屏 <2s（3G 模拟），作答切换无网络等待
- **样本漏斗约束**：端到端完成率约 49%，入库为显式 opt-in（预估 78%）→ **约 520 次「进入第 0 步」才换 200 份入库样本**。投放规划必须按 520 计，不是按 200。
- 动效禁止弹跳缓动 `cubic-bezier(0.68,-0.55,0.265,1.55)`

## 11. 内嵌已知坑

| 坑 | 指纹 | 根因 | 修法 |
|----|------|------|------|
| 版本号幻觉 | lucide-react | 凭记忆写版本号（曾误记 1.37.0，实测 1.43.0） | 一律 `npm view` 实测后回填 |
| 题单污染历史数据 | schema_version | 上线后改题不升版本 | 上线前定死题单；改题必升 `schema_version`，新旧样本不混跑 EFA |
| 前台误判档位 | band_basis | 冷启动样本少时切分位不稳 | N<30 用先验三等分，N∈[30,150) 用 P33/P67，N≥150 用 k-means |
| 分享卡片被深色模式污染 | Canvas 导出 | 直接用 DOM 截图会继承当前主题 | Canvas 绘制并硬编码浅色，或 `html-to-image` 前强制切主题 |
