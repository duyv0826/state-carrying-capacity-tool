# ADR-017: 种子数据开发模式 —— 继续做 k-means 线，但强制数据血缘标记

**Status**: Accepted (2026-09-21)

**Background**
真实样本 `scc.db` 在服务器 Docker 具名卷 `scc-data:/app/data`，本地无，且 N<150。问题是：L2（k-means 回写 + 常模对比）该继续用种子数据开发，还是等真实数据到位？

关键诊断：**风险不在"做不做"，在产出的性质不同。**
- T9 `calibrate-kmeans.ts` 是**工程组件**——它只认 N≥150 门控，脚本的正确性与喂进去的数据真假无关，种子数据足以证明代码正确
- T11 常模视图是 **UI 组件**——也能做，但它吐出的**数字**一旦被截图进学位论文，就是学术事故（虽非故意）

因此"措辞降级"这种靠人记住的方案不够。必须做**物理隔离**：让种子数据在视觉上、接口上、导出上都无法伪装成真实结论。

**Decision**

1. **不砍。** T9 / T11 继续用种子数据开发，`scc.db` 到位后一键切换。
2. **引入运行时 `DATA_SOURCE` 标记**（取值 `seed` | `real`），默认 `seed`。
3. **四级措辞门槛**（与源码常量对齐，不留中间模糊地带）：

| N 区间 | 允许措辞 | 可显示 | 禁止 |
|---|---|---|---|
| N < 8 | 「样本不足，暂不提供对比」 | 无对比数字 | 任何分布数字 |
| 8 ≤ N < 30 | 「同软件分布（描述性）」 | 均值、中位数、原始散点 | "常模"字样、分位数、推断统计 |
| 30 ≤ N < 150 | 「参考分布（描述性·非推断）」 | 分位数（须标注描述性） | "常模"字样、显著性检验 |
| N ≥ 150 | 「常模」 | 全量，可出推断统计 | — |

   区间取自源码：`MIN_N_FOR_EMPIRICAL=30`、`MIN_N_FOR_KMEANS=150`（`domain/bands.ts`），下界 8 取自 PRD §2.2 护栏。**措辞由常量驱动，禁止前端硬编码文案。**

4. **种子模式三条强制约束**（物理隔离，非约定）：
   - admin 看板顶部固定横幅：`演示数据 · 不可用于研究结论`（`DATA_SOURCE=seed` 时强制渲染，不可关闭）
   - **导出按钮 disabled**，且服务端导出端点在 seed 模式返回 403
   - API envelope 增补 `data_source` 字段——即使只截到接口响应也能自证

5. 种子文件命名强制 `*.seed.ts`，**禁止**与真实 db 同名，防止误连。

**Consequences**

正面：
- L2 不被外部依赖（洪兄导出 db）阻塞，可立即开工
- 四级门槛把 R2 裁决（n<8 措辞抑制 / N≥150 统计推断）补成完整光谱，消除 8–150 的模糊地带
- 物理隔离让"误用种子数据进论文"这件事**技术上不可能发生**，而非靠记忆

负面 / 成本：
- 新增约 0.5 人日（横幅 + envelope 字段 + 导出守卫 + 常量驱动措辞）
- 四级措辞需前端按常量分支渲染，比单一文案略复杂
- 真实 db 到位后需回归验证切换路径（已列入 T11 验收条件）

**Related ADRs**: ADR-013（k-means 回写纯 TS）、ADR-015（常模对比 SQL/TS）
