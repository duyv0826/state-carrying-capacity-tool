## 四、建议开工顺序

1. **先做 G0 五件**（半天）——成本最低、收益最高，避免全链路返工
2. **冲 M1**：T1 → T2 → T3 → T4 → T5，目标**真实跑通一次完整回访**。这是 v2.0 的核心价值，也是唯一能证明闭环成立的证据
3. **M1 后并行**：L2（后端数据）与 L3（前端看板）分两路推进
4. **L4 收口**穿插进行，T16 等洪兄外部办理

## 六、附：种子数据为何可以继续做（ADR-017 摘要）

**决策：不砍 k-means 线，继续用种子数据开发。** 但必须理解为什么安全——

### 分界线是「代码 vs 结论」，不是「措辞」

| 产出 | 性质 | 种子数据够不够 | 理由 |
|---|---|---|---|
| T9 `calibrate-kmeans.ts` | **工程组件** | ✅ 完全够 | 脚本只认 N≥150 门控，其正确性与喂进去的数据真假**无关** |
| T11 常模视图 | **UI 组件** | ✅ 够（做界面） | 但吐出的**数字**不能进论文 |
| 视图里的分布数字 | **统计结论** | ❌ 不够 | 这是唯一不能碰的东西 |

所以真正要防的不是"做不做"，而是**种子数字被误当成真实结论**。靠"记得别用"防不住——必须物理隔离。

### 四级措辞门槛（由源码常量驱动，禁止硬编码）

| N 区间 | 允许措辞 | 可显示 | 禁止 |
|---|---|---|---|
| N < 8 | 「样本不足，暂不提供对比」 | 无对比数字 | 任何分布数字 |
| 8 ≤ N < 30 | 「同软件分布（描述性）」 | 均值、中位数、散点 | "常模"字样、分位数、推断统计 |
| 30 ≤ N < 150 | 「参考分布（描述性·非推断）」 | 分位数（标注描述性） | "常模"字样、显著性检验 |
| N ≥ 150 | 「常模」 | 全量，可出推断统计 | — |

区间取自 `domain/bands.ts`：`MIN_N_FOR_EMPIRICAL=30`、`MIN_N_FOR_KMEANS=150`；下界 8 取自 PRD §2.2。**这一档补上了原 R2 裁决留下的 8–150 模糊地带。**

### seed 模式三条强制约束（T19）

1. admin 看板顶部固定横幅 `演示数据 · 不可用于研究结论`，**不可关闭**
2. 导出按钮 disabled，服务端导出端点在 seed 模式返回 **403**
3. API envelope 增补 `data_source` 字段——只截到接口响应也能自证

**一句话**：让"误用种子数据进论文"在技术上不可能发生，而不是靠人记住。
