## 2. 研究背景与目的

**理论锚点**：本研究以 Rabardel (1995) 的*工具生成理论（instrumental genesis）*为核心框架，区分 *artifact*（原始工具）与 *instrument*（被使用者改造、承载其习惯与责任后的工具）。由此提出 **"状态承载量（state-carrying capacity）"** 概念：工具保留意愿与其状态承载量正相关，与任务一次性程度负相关。

**研究目的**：通过自测工具采集用户对常用软件"状态承载量"的主观评估，验证"状态承载量越高 → 用户保留/迁移意愿越强"的研究假设，为学位论文提供一手量化数据。

**研究假设（示例）**：
- H1：状态外显程度（因子 A）越高的软件，用户更换意愿越低。
- H2：产出形态（因子 B）越"资产型"的软件，保留意愿越强。
- H3：制度/协作嵌入（因子 C）越深的软件，迁移成本越高、保留意愿越强。

---

## 3. 研究工具与设计

- **工具形态**：Web 自测问卷（单页应用 + 极薄后端），用户选择/输入一款常用软件后完成 9 题 Likert 量表（3 因子，每因子 3 题），并填写 3 道分层背景题（S1/S2/S3）+ 1 道选填题（S4）。
- **流程步数**：14 步（含中场结果预览激励）。
- **计分**：前端本地即时算分 + 服务端独立复算（双算一致），总分 9–45，先验切点 `[21, 32]`（≤21 高危 / ≤32 观察 / >32 安全）。
- **匿名性**：全程不要求实名，不采集任何直接标识符（见第 5 节）。

## 5. 数据收集内容（核心，依据真实代码）

### 5.1 默认姿态（IRB 最安全默认）

工具内置 `collection_enabled` 开关，**默认 `false`**。
- 关闭时：前端**根本不发起任何采集 POST 请求**（AC-09 传输最小化），服务端对采集端点一律不落库（返回 `3001`）。
- 结论：**即便不备案，工具 100% 可用、零数据离开浏览器**。备案通过后再将环境变量 `COLLECTION_ENABLED=true` 开启。

### 5.2 开启后实际存储字段（`submissions` 表）

| 字段 | 内容 | 是否 PII | 说明 |
|------|------|----------|------|
| `session_id` | 随机 UUID | 否 | opaque，不可回溯到个人 |
| `created_at` / `client_submitted_at` | 时间戳 | 否 | |
| `schema_version` | 2 | 否 | |
| `consent_version` / `consent_mode` | `v1.0-2026-09` / `implied` | 否 | 知情同意标记 |
| `software_name` / `software_name_norm` / `software_category` / `is_custom_input` | 软件名与类别 | 否 | 软件信息，非个人信息 |
| `answer_1`…`answer_9` | 9 题作答（1–5） | 否 | |
| `factor_a/b/c_score` / `total_score` / `band` / `band_basis` / `n_at_scoring` | 计分结果 | 否 | |
| `s1_learning_type` / `s2_tenure_bucket` / `s3_frequency_bucket` / `s4_adoption_type` | 分层背景 | 否 | S4 可为空 |
| `duration_ms` / `device_type` / `ua_family` | 行为/环境（粗粒度） | 否 | |
| `region_bucket` | 地区 | 否 | **被试自愿填写，不从 IP 推断**（代码注释明确） |
| `sequence_index` / `straightlining_flag` / `rapid_flag` / `quality_flags` | 数据质量标记 | 否 | 算法生成，非 PII |
| `feedback_text` | 自由文本 | 可选 | 用户主动填写，可留空 |
| `followup_token` | 后续联系令牌 | 可选 | 仅当用户主动选择"愿意被联系"时生成 |
| `excluded` | 质控剔除标记 | 否 | |

**关键声明**：表中**无任何姓名、邮箱、手机号、IP 地址、精确地理位置**。唯一可能含联系方式的 `followups` 表（`contact_encrypted`）**仅在用户显式勾选"愿意后续联系"时创建**，且联系方式经加密存储，并设有 `contact_purge_after` 自动清理时限。

### 5.3 中途放弃埋点（`abandon_events` 表，AC-13）

仅在采集开启时记录：`session_id`、`last_question_index`、`duration_ms`、`software_name`。**不含任何作答内容**，用于评估问卷流失，无惩罚含义。

## 6. 知情同意

- **形式**：首页勾选同意框方可开始（`consent_mode` 默认 `implied`，即勾选即视为同意）；如需更严格可设 `CONSENT_MODE=explicit`。
- **版本管理**：`consent_version` 与本文档版本对齐（`v1.0-2026-09`），后续变更需同步更新并重新征得同意。
- **退出权**：用户可随时关闭页面放弃（AC-13），放弃不记录作答内容、不影响任何权益。
- **告知内容**：首页需向用户说明"本问卷匿名、约 [X] 分钟、数据仅用于学术研究、可随时退出"。

## 7. 隐私与数据安全

| 措施 | 实现 |
|------|------|
| 无直接标识符 | 不采集姓名/邮箱/IP/手机号 |
| 地区不取 IP | `region_bucket` 由被试自愿填写 |
| 最小化传输 | 关闭时前端零字节离站（AC-09） |
| 蜜罐防爬虫 | `hp` 字段命中即 `200` 不入库，剔除机器流量 |
| 加密存储 | 后续联系方式 `contact_encrypted` 加密 |
| 部署位置 | 香港/新加坡轻量机，免 ICP 备案，降低数据主权复杂度 |
| 存储形态 | 单文件 SQLite，便于整体导出/删除/销毁 |
| 访问最小化 | 仅研究者持有服务器与数据库访问凭据 |

## 8. 风险与受益

- **风险**：极低。仅涉及匿名自评，无干预、无欺骗、无身心风险，无 vulnerable population 定向招募。
- **受益**：参与者获得自身软件"状态承载量"即时反馈；研究为 AI 时代工具保留机制提供学术证据；对研究者构成学位论文核心数据。
- **不利益**：无。

3. 部署主机：香港/新加坡轻量机，Caddy/Nginx 做 HTTPS + 域名解析；代码包 host-agnostic，切主机=改 DNS。

5. 上线前复测：`POST /api/v1/submissions` 合法应 `201`；`hp:"bot"` 应 `200` 不入库。
