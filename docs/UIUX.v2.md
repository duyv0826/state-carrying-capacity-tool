## 0. 设计基线重申（v1.0 不可推翻项）

v2.0 是增量迭代，**以下全部继承，不重新决策**：

| 基线项 | 锁定值 | 对 v2.0 的约束 |
|--------|--------|----------------|

## 1. 联网调研结论（3+ 产品 / 范式提炼）

### 1.1 调研对象

| 产品 / 范式 | 类型 | 可借鉴点 |
|-------------|------|----------|
| **Observable Plot / Observable 10 调色板** | 开源可视化库 + 数据叙事 | ① 分类色板设计原则：色相角尽量分散、小标记也分得清、色觉障碍友好、深浅背景都可用；② 同一颜色跨图必须同义（颜色协调原则） |
| **Metabase** | 无代码分析看板 | ① 卡片=1px 描边+留白面板，无浮夸阴影；② 顶部筛选栏常驻；③ 概览→下钻的分层信息架构 |
| **Datawrapper** | 出版级图表工具 | ① 图表默认即"可发布"质感：克制网格、零基线（bar 从 0 起）、轴标签清晰；② 分布用直方图/箱线而非饼图 |
| **量表开发 EFA/CFA 范式**（Boateng 2018 / DeVellis / Ohio State 量表开发流程） | 学术方法论 | ① 切点校准是显式步骤（先验三等分→经验分位→k-means）；② 需展示 KMO、Bartlett、Cronbach's α、CFI/TLI/RMSEA/SRMR；③ 三因子相关矩阵是量表质量核心证据 |
| **Dashboard 设计最佳实践**（dataanalyst.co.uk 5 秒规则 / expressanalytics） | 通用看板 | ① 最重要 KPI 放左上（F 型扫描起点）；② 图表选型矩阵：比较用柱、趋势用线、分布用直方图、离群用散点；③ 颜色从不作唯一编码（WCAG 1.4.1） |

### 1.2 提炼的设计决策（落地到 v2.0）

1. **颜色协调**：admin 看板所有图表共用一套语义——档位/风险图一律用 `risk.*` 三色（与公开结果页量表条同义）；相关性/强度图用墨蓝单色序进（sequential）色阶；多系列分类图用墨蓝+冷调青+岩灰（避开 risk 三色，避免"红色=危险"误读为"因子差"）。
2. **零基线 + 克制网格**：所有柱状/条形图 y 轴从 0 起；网格线用 `--color-border-subtle`，轴文字用 `--color-text-tertiary`。
3. **分层 IA**：概览 KPI（战略层）→ 量表质量/漏斗（战术层）→ 反驳文本（诊断层）→ 导出（上下文层），符合 5 秒规则。
4. **可核验优先**：每个指标旁带"定义/口径"小字与 `Last computed` 时间戳，呼应测量仪器气质。
5. **复用家族工艺**：看板面板=公开页 Card（1px border-default + 无阴影）；漏斗段/进度段沿用 ProgressTrack 的"实色=已发生，border-subtle=未发生"语言。

## 3. 方向一：纵向回访闭环

### 3.1 设计约束
- **轻量、不破坏匿名感**：用户通过邮件里的随机 token 链接进入，`followups` 表与 `submissions` 物理分表、仅 token 关联（继承 v1.0 隐私最小化）。回访页**不得**出现任何"我们记得你是谁"的措辞。
- **单一调节变量**：PRD §6.4 核心——验证"同为高危分，A 类（学操作成本）用户 6 个月后真的换了吗"。故回访问卷是**分类题，不是 Likert**（与 S1 同构，避免程度轴污染）。

### 3.2 回访问卷页 `/followup/:token`（IA + 视觉方向）

```
[进度：单页，无 ProgressTrack（回访是独立轻量流程，不复用 14 段轨）]
[12px mono tertiary：纵向回访 · 匿名]
[24px]
[18px/30 500 primary：你去年测的 {software} ，现在还在用吗？]
[8px]
[13px tertiary：这是一年前的回访，约 20 秒。你的回答只和当时的结果统计在一起，不关联任何个人。]
[24px]
┌────────────────────────────────────────────────────┐
│ Ⓐ  还在用，和去年差不多                      RotateCcw │  ← 陈述行(复用 S1 工艺)
│ ───────────────────────────────────────────────    │     高 56px，整行可点
│ Ⓑ  还在用，但用得少了                            │
│ ───────────────────────────────────────────────    │
│ Ⓒ  换了个功能类似的软件                        │
│ ───────────────────────────────────────────────    │
│ Ⓓ  基本不怎么用了 / 已经彻底不用了             │
└────────────────────────────────────────────────────┘
[24px]
[18px/30 500：和去年测的时候比，你对它的「状态承载量」判断变了吗？]  ← 校准问(可选)
[chip 单选，复用 S2/S3 工艺：变高了 / 差不多 / 变低了 / 没概念]
[32px]
[ 提交回访 ]  ← accent 实心主按钮 h44，16px Check
```

- **复用**：陈述行（S1 的 A/B/C 纵向行工艺，序号 A/B/C、选中态=浅底+accent 文字）、chip 单选（S2/S3）、内联提示块（risk 色 subtle 底）。
- **不复用**：Likert（回访是分类非程度）、ProgressTrack（单页轻量，不渲染 14 段轨，避免"又来一套量表"的压迫感）。
- **空态/错误态**：token 失效 → 内联提示块（risk-high-subtle）"这个回访链接已失效或已被使用"；提交中 → 按钮内 Loader2 旋转（复用 4.1.6 提交中态）。

### 3.3 回访结果反馈页 `/followup/result`（IA + 视觉方向）

**核心原则**：展示**群体趋势**，绝不以任何形式暴露"你本人"的数据。页面开场白即声明"下面是和你一样去年测过的人整体的走向"。

```
[容器 680px，复用 PageLayout]
[12px mono tertiary：纵向回访 · 群体趋势]
[24px]
[18px/30 500 primary：去年测出「高危」的人，一年后怎么样了？]
[8px]
[13px tertiary：下面是基于 {N} 份有效回访的群体走向，不含任何个人作答。]
[24px]
┌─ 档位流向（复用公开页量表条几何，但渲染为「去年档位 → 今年还在用占比」）─┐
│  高危区  去年 {Nh} 人 → 其中 {x}% 现在还在用        [横向占比条 accent] │
│  观察区  去年 {Nw} 人 → 其中 {y}% 现在还在用        [横向占比条 accent] │
│  安全区  去年 {Ns} 人 → 其中 {z}% 现在还在用        [横向占比条 accent] │
└──────────────────────────────────────────────────────────────────────┘
[24px]
[13px tertiary：和「还在用」相比，选择「换了个类似软件」或「彻底不用」的比例，]
[13px tertiary：在高危区最高——这正支持量表对「状态承载量低」的预测方向。]
[32px]
[ 查看你自己的原始结果（如需）]  ← ghost 文字按钮，仅深链回 /result/:token（本地）
```

- **图表规范**：占比条用墨蓝序进（accent-subtle→accent-default），不用 risk 三色（此页讲的是"留存"不是"风险"，避免语义串色）。流向数字用 mono + tabular-nums。
- **防误读**：每个占比条右侧紧跟绝对人数（mono），并注明 N；不加任何"你属于 X%"类措辞。

## 4. 方向二：实证分析升级

### 4.1 同软件常模对比（公开结果页内嵌模块）

**位置**：`/result` 维度解释之后、分享之前，作为一个可折叠 `<details>` 模块（与 v1.0 方法论区块同工艺），默认收起。
**触发条件**：该软件 `software_key` 的有效样本 ≥ 15 份才渲染；否则整块不出现（不做假数据）。
**防误导硬要求**：标题必须写明"**同软件常模**（仅测过这款软件的人），不是全体用户常模"。

```
<details> 同软件常模 · 测过 {software} 的其他人
  ┌─ 分布直方图（0-100 分，bin=5）──────────────────────┐
  │  用墨蓝柱(accent) + 背景 band 分区阴影(risk 三色@18%) │
  │  你的分数用竖线游标标出（复用结果页量表条游标几何）   │
  │  轴：左 0 · 承载量低 ／ 右 100 · 承载量高            │
  └────────────────────────────────────────────────────┘
  [13px tertiary：N={n} 份 · 中位数 {med} · 你的分数高于 {p}th 百分位]
  [13px tertiary：这是「同软件」小样本分布，不可外推到所有软件用户。]
</details>
```

- **复用**：结果页量表条游标几何 + risk 三色 band 分区（与公开页同义）。
- **图表**：直方图（Datawrapper 范式：零基线、克制网格）。多软件并排对比**不做**（小样本误导）。

### 4.2 切点校准过程可视化（admin / 方法论）

**位置**：`/admin/scale-quality` 顶部，一张"校准演进"图 + 三步文字说明。这是论文"切点校准"一节的可视化自证。

```
切点校准演进（0-100 分轴，复用 risk 三色 band 分区）
  先验三等分(prior)      : |── 安全 0-21 ──|── 观察 22-32 ──|── 高危 33-45 ──|  (9-45 映射后)
  经验分位(empirical)    : |── 安全 0-30 ──|── 观察 31-60 ──|── 高危 61-100 ─|  (P33/P67)
  k-means(k=3)          : |── 安全 0-28 ──|── 观察 29-63 ──|── 高危 64-100 ─|  (N≥150 生效)
  ───────── 你的样本当前用：empirical（N={n}）─────────
```

- **图表**：一条 0-100 轴 + 三组切点标记（垂直线），用 mono 标注切点值；band 分区用 risk 三色 @18%（与公开页量表条完全一致）。
- **状态**：`calibration.method = prior|quantile|kmeans` 从 DB 读取，当前生效的一组用 accent 实线强调，其余两组用 border-strong 虚线弱化。与 v1.0 §4.3.5 "档位依据理论切点"声明呼应。

**导航项 → lucide 图标（均 ^1.43.0，20px）**：概览 `LayoutDashboard`、样本质量 `FlaskConical`、漏斗诊断 `Filter`、反驳文本 `MessageSquareWarning`、导出 `Download`、合规 `ShieldCheck`。
**KPI 图标（16px）**：总样本 `Users`、本周新增 `TrendingUp`、入库率 `CheckCircle2`、完成率 `Activity`。

### 5.2 关键页面视觉方向

**A. 概览 Overview**
- KPI 行：4 个大数字卡（复用 Card 1px border）。数字用 `--font-mono` + `font-size-2xl`(26px) + `tabular-nums`（复用结果页分数排版，但降一档，不与结果页 44px 抢戏）。每个数字下方 13px tertiary 标注口径（如"有效入库样本，不含放弃"）+ 右侧 16px 趋势图标（升 `TrendingUp`/降 `TrendingDown`，用 accent 或 risk 依正负，但**必须配文字 +/-%** 满足 WCAG 1.4.1）。
- 档位分布：横向堆叠条（risk 三色）优于 donut（Tufte 数据-墨水比；且 risk 三色在条上天然可读）。条上方标注各档人数+占比（mono）。
- 样本漏斗：见 §5.3。

**B. 样本与量表质量 ScaleQuality**
- 三因子相关矩阵：3×3 heatmap。单元格填墨蓝序进色（弱=accent-subtle，强=accent-default），每格叠加 `r=xx` 文字（含符号），避免颜色单编码。对角线=1.00 用 border-strong 弱化。下方一行 13px tertiary 注明"因子间相关应 < .85，过高提示区分效度不足"。
- 切点校准演进：§4.2 图。
- Cronbach's α：三个小卡（A/B/C 因子各一张），大数字 + "α≥.70 可接受"阈值线（用 risk.safe 细标达标、risk.watch 标临界）。

**C. 漏斗与放弃诊断 Funnel**
- FunnelTrack 组件（**ProgressTrack 工艺衍生**，非复用原组件）：纵列 14 步，每步一个横条，宽度∝留存人数；已发生步=accent 实色，当前步=accent-hover，未达步=border-subtle。"背景段"（S1-S3）视觉降级为 border-subtle（继承 v1.0 AC-04 语言）。
- 放弃诊断：按 `last_question_index` 聚合的 bar 图（每题一个柱，高度=该步流失人数），最差步用 accent 实色、其余 border-strong。坐标轴 0 起。

**D. 反驳文本 Rebuttals**
- 不是图表，是 table（复用 Card 边框 + 原生 `<table>` 语义）。列：提交时间 / 软件 / 档位(risk 色点+文字双编码) / 反驳文本(truncate + 展开) / 操作(导出单行)。顶部筛选：按档位、按关键词、按时间。
- 空态：border-subtle 虚线框 + 16px `Inbox` + "暂无反驳文本"。

**E. 导出 Export**
- 三个主按钮（复用结果页分享按钮工艺）：`Download` CSV / `Download` JSON / `FileCode` codebook。点击后 Loader2→Check 微反馈（≤2s 复原，复用 4.2.4）。

## 6. 方向四：合规与遗留

### 6.1 IRB 备案告知页微调（/legal/irb）
- **不新增架构**，仅微调 v1.0 知情同意文案与一处 footer 链接：当 `config.irb_status = filed|approved` 时，首页知情同意块与结果页方法论区块追加一行 13px tertiary：「本研究已通过澳门科技大学人文艺术学院伦理审查备案（备案号 {irb_no}）」，左侧 16px `ShieldCheck`(accent)。`irb_status = pending` 时不显示（不提前声称）。
- 复用 v1.0 内联提示块工艺，不新造组件。

### 6.2 i18n 适配评估（若做）
- **现状**：v1.0 布局全部基于 max-width 容器（question 680 / result 880 / share 540）+ 流式 padding，**无硬编码像素宽依赖文字**，天然适配 key-swap i18n 层。
- **风险点**（若做需处理）：
  1. Likert 5 格等距在长英文标签下会换行破坏等距性 → 复用 v1.0 移动端"纵向堆叠"作为 i18n 兜底布局。
  2.  mono N 计数、档位游标几何为 LTR，无需改；但阿拉伯语等 RTL 不在目标范围（中文/英文），不处理。
  3.  文案膨胀：按钮用 `min-width` + 自适应而非固定宽；label 走 i18n key，不写死。
- **结论**：i18n 优先级低（PRD RICE 0.40），布局兼容成本小；建议**维持不做**，仅在组件层避免固定宽即可为未来预留。

## 8. admin 看板配色与图表规范（必须 token 化）

### 8.1 配色总则（禁紫粉渐变、禁第二品牌色）
- **唯一强调色**：墨蓝 `accent.*`（与公开端一致）。
- **风险语义色**：`risk.*` 三色——**仅**用于"档位/风险/留存对比"语义图（档位分布、切点校准 band、回访流向），且每处必配文字标签+位置编码。
- **相关性/强度图**：墨蓝单色序进 `data.seq.1→5`（§9 新增），绝不引入红绿发散（避免与 risk 串义）。
- **分类多系列图**：墨蓝 + 冷调青 `data.cat.teal` + 岩灰 `data.cat.slate`（§9 新增），避开 risk 三色与紫粉。
- **坐标轴/网格**：`data.plot.grid`(=border-subtle) / `data.plot.axis`(=text-tertiary) / `data.plot.bg`(=bg-surface)。
- **禁用**：任何 `linear-gradient` 主视觉、emoji 图标、纯黑纯白直写（经 token）。

### 8.2 图表选型矩阵（对齐调研结论）

| 目标 | 图表 | 颜色 | 备注 |
|------|------|------|------|
| 档位分布 | 横向堆叠条 | risk 三色 | 零基线、标人数+占比 |
| 三因子相关 | 3×3 heatmap | data.seq 墨蓝序进 + 格内 r 文字 | 对角线弱化 |
| 切点校准 | 0-100 轴 + 三组垂直线 | risk band@18% + accent 生效组 | 复用量表条几何 |
| 同软件常模 | 直方图(bin=5) | accent 柱 + risk band 阴影 + 游标 | 零基线 |
| 样本漏斗 | FunnelTrack | accent 实色 / border-subtle 未达 | 背景段降级 |
| 放弃诊断 | 按题 bar | accent 高亮最差步 / border-strong | y 从 0 起 |
| 留存流向 | 横向占比条 | data.seq 墨蓝序进 | 标绝对 N |

### 8.3 图表无障碍
- 所有图表容器带 `role="img"` + `aria-label` 简述；heatmap 额外提供数据表 `<details>` 兜底。
- 颜色从不作唯一编码（WCAG 1.4.1）：heatmap 格内文字、占比条旁人数、band 分区文字标签。
- 图表内数字一律 mono + tabular-nums；轴标签 ≥12px tertiary（对比度达标）。

## 10. v1.0 Token 够用性确认

| 需求 | v1.0 是否够 | 结论 |
|------|-------------|------|
| 主色/风险色/中性色阶 | 够 | 看板档位图直接复用 risk 三色 |

**结论**：v1.0 基础系统（色彩哲学/字体/间距/动效/组件）完全够用且必须延续；仅需为"图表数据可视化"补 ≈9 个语义 token（§9），不引入任何新品牌色、不触及 risk 三色语义、不破坏现有 112 leaf。

## 13. 无障碍与动效要点（v2.0 追加）

- **动效**：看板图表入场用 `opacity 0→1` + `translateY(8px→0)` 200ms（`motion-duration-base` / `entrance`），**禁止**量表条 600ms 仪式感（那仅给公开结果页一次）。`prefers-reduced-motion` 下全部直接落位（继承 design-tokens.css 媒体查询）。
- **键盘**：看板侧栏可 `↑↓` 导航 + Enter；筛选 chip 复用 S2/S3 键盘映射；图表提供 `<details>` 数据表兜底。
- **对比度**：新增 `data.cat.teal`(深色 #4FD1CB) / `slate`(深色 #94A3B8) 在深色底上须 ≥3:1（控件边界）/4.5:1（文字），合入前用对比度工具核验。
- **匿名纪律**：回访/看板导出**绝不**出现可关联个人的字段（followups 物理分表，导出排除 token 列，继承 v1.0 隐私最小化）。
